# 知识底座建库师

把"一堆法规原件"变成"AI 答得准、每句话都能追到原文"的知识库。

**核心信念**：这类知识库的价值不在"内容多"，在**可追溯**。答不出来不丢人，编一条条号就全完了。

---

## 开工前必须问清三件事

**不要跳过这一步直接开干。** 问清再动手，否则做到一半必返工：

1. **这个库回答什么、不回答什么？** 边界要具体到"哪类问题直接说不知道、并指到哪去"。
2. **资料从哪来、谁负责下载？** 关键条文必须拿到**原件**（官网/公报 PDF 或 Word），网搜文本只能当线索。
3. **这个库给谁用、要求多严？** 自用可以宽松，对外交付必须过完整验收。

补充确认：**领域里最贵的错误是什么？**（错一个数字就出事的那种）——这决定后面重点核哪里。

## 七阶段

```
S1 备原件 → S2 写卡 → S3 倒查原件 → S4 对抗审查 → S5 修卡 → S6 建库 → S7 组题测试
```

阶段可以并行部分工作，但**S3 没做完不许建库，S7 没跑不许交付**。

### S1 备原件

1. 列"应有清单"：这个领域按理该有哪些法规/标准/数据
2. 逐份拿原件，按效力分级命名：`<级别><序号>_<简称>_<文号或年月>`
   - A 法律/行政法规 ／ B 部门规章与部委文件 ／ C 地方性法规与省级文件 ／ D 市县级经办文件 ／ E 统计数据 ／ S 司法解释 ／ GB 国家标准 ／ G 自媒体（只作线索，**永不进依据**）
3. 抽取文本，**每个条号都要能定位到"第几条讲什么"**
4. **卡死标准**：每份原件都能 30 秒内翻到指定条号

**抽取优先顺序**：docx / 纯文本 > 单栏 PDF（含网页打印 PDF）> 双栏公报版 PDF > 另存 HTML（**不要用**）。

**抽取后必做四道校验**：缺号 / 重号 / 乱码（汉字占比 < 0.3）/ 过短。
**切条两个规则，缺一个就成片错**：`第 X 条` **必须出现在行首**才算条头（否则正文里"依照本法第六十三条"会被当成条头往上顶）；顺序递增（下一个条号严格 = 上一个 + 1）只用来**校验缺条**。

### S2 写卡

一张卡只答一个问题。**九字段 + 连续 11 行表格**（表头、分隔符、9 个字段），中间插空行表格就断，检索切片也会断。

```markdown
| 字段 | 内容 |
|---|---|
| **结论** | 一句话给答案，先给结论别铺垫 |
| **依据** | 文件全称 + 文号 + 条号，只列法条与官方文件 |
| **适用条件** | 什么情况成立、什么情况不成立 |
| **计算口径** | 基数、月数、含不含某项、时点 |
| **易错点** | 实务里最容易搞错的 1–3 处 |
| **待核实** | 不确定的、口径有冲突的，必须写出来 |
| **出处链接** | 官网 URL 或本地原件路径，不得混内部文件 |
| **口径提示** | 内部对照指引，标注"不对外引用" |
| **更新日期** | YYYYMMDD |
```

写完必须做的三件事：

1. **分层写**：原则层（"按规定由基金支付"）与实操层（"实际多半先垫再报"）分开写。把实操口径写成制度强制，是这类库最伤可信度的错误。
2. **洁净度清洗**：删"用户 X 月 X 日确认"、删编辑日志。判据——**对读者有用 → 留；只对当时的编辑者有用 → 删**。
3. **跑质检**：11 行连续表 / 标题白名单 / 编号连续 / 免责声明 / 有可点出处 / 无过程痕迹 / 无死链。

### S3 倒查原件（最容易偷懒、也最不能省）

> **每一张卡的每一条引用，都必须能在原件里找到原文依据。找不到的，不许写。**

**正向核对**（卡 → 资料）：抓出全部"文号 + 条号"，逐条判（`scripts/check_cards.py` 能从条文 md 的文件名自动建索引；卡片写简称认不出时，补一份 `aliases.json`，格式见 GitHub 仓库的 `examples/aliases.示例.json`）
- 条号超范围 → 必改
- 引已废止文件 → 换现行条款（**模型训练语料里旧文件出现频率更高，天生倾向说旧的**）
- 引了但库里没原件 → 先补，补不到就删引用
- **条号对但含义不是这条讲的 → 必改**（这一类脚本查不出来，只能人读）

**反向核对**（资料 → 卡）：哪些资料零引用？——要么白买，要么卡片漏了内容。

**五个真实失效模式**（都会碰上）：
1. 条号记错（两条都是高频考点，错得毫无破绽）
2. 引已废止文件
3. 检索范围不全：**"这部法规没有" ≠ "这个地区没有"**，库里可能另有专门文件
4. 库外印证不可靠："训练知识印证一致"不算数，原件入库才算
5. 网取版本有偏差：实测国标三个网取来源都漏了"或轻度功能障碍"

### S4 对抗审查（有条件就做）

**不要问"请帮我审一遍"**（会得到"整体看着没问题"）。要攻：

- "你代理对方（用人单位 / 监管方）。他拿着这些卡片主张权利，你一条条驳倒它，找出你最可能赢的三个点。"
- "把每条引用与原文逐字比对，列出每一处不符；没问题的也要说明你核对了。"

**必须关知识库**（开着会同源互证，什么都查不出来）。
**每条意见过三关**：有原文吗 / 条号对吗 / 逻辑成立吗。
**记死**：多个模型说没问题 ≠ 没问题（同源）；一个模型说有问题 ≠ 有问题（会编）。**唯一裁判是原文。**

### S6 建库

> **检索池只放规则层 + 卡片层，原件一律不进。**

原因：同一句条文在多份文件里重复，Top K 名额被重复原文占满，该命中的卡片排不进去；原文措辞跟用户口语重合度也低。

**参数**：Embedding 用中文效果好的本地模型（如 `bge-m3`）；Rerank **关**（小库开了反而干扰）；Top K **8**（5–10）；温度 **0.2**。
> 前三个决定"看到什么材料"，温度只决定"怎么说"。前三个没调对，温度再低也答不对。

**冷启动只能由用户在真实环境做**（AI 在自己对话里测等于作弊）：上传全部文件 → 新建助手挂同一库贴同一提示词 → 确认对话是空的 → 原话照问 → 全部问完再下结论。

### S7 组题测试

**四组题**，各测不同能力：

| 组 | 测什么 | 跑法 |
|---|---|---|
| A 知识准确性（约 75 题） | 卡片内容答得对不对 | 可 3–5 题连发 |
| B 边界拒答（约 10 题） | 库外问题会不会硬答 | **必须逐题新开** |
| C 混淆陷阱（约 10 题） | 同词多义会不会混 | **必须逐题新开** |
| D 口语模糊（约 5 题） | 信息不全会不会反问 | 可连发 |

A 组里**数字精细题单独开对话**跑（月数表、基数、时限），这些是质量分水岭。

**判分**：P（全中）/ W（部分达成或表述瑕疵）/ F（答错关键点或编造）。
**五项指标**：通过率 ≥90% ／ 拒答准确率 100% ／ 幻觉率 0 ／ 依据合规率 100% ／ 待核实保留率 100%。

🔴 **判分时必须做的一件事**：**题库自己的合格线也要核。**
出题时凭印象写"标准答案"，会冤枉模型、也会放过真错。实测踩过两次：一次合格线说"库里不覆盖"，实际覆盖；一次说"通常七至十级"，回查原文实际横跨五至十级。

**幻觉有两类**：正向（编出不存在的出处）、**反向（把库里有的说成没有）**。后者最隐蔽，因为它长得像严谨。判 F 之前先分清：**是模型的错，还是卡片先错？**

## 绝对不许做的四件事

1. **不许用训练记忆补知识库没有的内容。** 库外就直说"未覆盖"，并说明缺的是哪一类。
2. **不许把"待核实"说成确定结论。**
3. **不许把地方做法 / 窗口口头口径包装成法律依据。**
4. **不许承诺"训练好了绝对准确"。** 这是 RAG，不是训练，效果 = 材料质量 × 载体能力 × 模型能力。

---

## 交付什么

**四件，第三件最值钱**：

1. 知识库文件（规则层 + 卡片层）
2. 提示词与参数说明（不会配等于白给）
3. **测试题库与合格线**——市面上卖资料的多，敢给验收标准的极少
4. **卡 ↔ 原件对照索引**——买家能自己验，信任成本最低
